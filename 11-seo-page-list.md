# SEO Page List

Target pages organized around commercial search intent rather than pure technology descriptions. Each page needs a specific buyer/problem framing, not just a feature list.

| URL | Primary intent / buyer |
|---|---|
| `/devops-staff-augmentation` | Hiring manager needing DevOps engineering capacity |
| `/cloud-engineer-staff-augmentation` | Hiring manager needing cloud engineering capacity |
| `/sre-staff-augmentation` | Hiring manager needing SRE capacity |
| `/remote-devops-engineers` | Buyer searching for remote/distributed DevOps talent |
| `/devops-engineering-services` | Buyer needing a DevOps platform built or improved |
| `/cloud-infrastructure-services` | Buyer needing general cloud infrastructure work |
| `/site-reliability-engineering` | Buyer needing reliability/observability improvements |
| `/kubernetes-consulting` | Buyer needing Kubernetes expertise |
| `/openshift-consulting` | Buyer needing OpenShift expertise |

| `/azure-cloud-migration` | Buyer migrating to Azure |

| `/terraform-automation` | Buyer needing IaC/Terraform work |
| `/kubernetes-platform-engineering` | Buyer building an internal developer platform |

## Per-page requirements for developer handoff
- Unique page title and meta description per URL
- H1 matching primary search intent, not a generic service name
- Internal links to the relevant service hub page and to the Staff Augmentation page
- Schema: Organization + Service (or JobPosting schema only where actually applicable, e.g. staff augmentation pages, if legally appropriate)
